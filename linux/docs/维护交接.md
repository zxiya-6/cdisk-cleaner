# Linux 版维护交接文档

本文档面向后续维护者：说明工程结构、构建流程、打包与验证方式，以及已知的坑。

## 一、工程结构

## 二、开发环境与构建

开发在 Windows 卷 `D:\dev\cdisk-cleaner\linux`，构建必须在 WSL 原生文件系统：

```bash
# 1. 同步源码到构建树（rsync，勿在 /mnt/d 上直接构建）
rsync -a --delete --exclude bin --exclude obj \
  /mnt/d/dev/cdisk-cleaner/linux/ /home/cleanmaster/build/linux/

# 2. 构建
cd /home/cleanmaster/build/linux
dotnet build            # 0 警告 0 错误

# 3. 测试
dotnet test tests/CleanMaster.App.HeadlessTests   # GUI 5/5
bash tests/e2e.sh                                 # CLI e2e 6/6
dotnet src/CleanMaster.Cli/bin/Debug/net8.0/CleanMasterCli.dll selftest  # 9/9
```

工具链：.NET SDK 8.0.131（packages.microsoft.com 源）、rsync、ImageMagick（截图/图标）、
rpmbuild（`apt install rpm`）、bsdtar+zstd（`apt install libarchive-tools zstd`）、
appimagetool（下载缓存于 `~/packages/appimagetool`，8.8MB 完整版，勿用截断文件）。

## 三、打包

```bash
bash installer/build-all.sh   # 产物在 /home/cleanmaster/packages/dist/
```

- 发布为 **self-contained**（不依赖系统 .NET），CLI 72MB / GUI 92MB。
- 包内容统一 `usr/bin/{cleanmaster,cleanmaster-gui}`（wrapper）+ `usr/lib/cleanmaster/{cli,gui}` + desktop/图标/文档。
- `.deb` 用 dpkg-deb；`.rpm` 用 rpmbuild（spec 在脚本内联）；Arch 手工构造 `.PKGINFO/.MTREE`；
  AppImage 用 appimagetool（WSL 无 FUSE 时先 `--appimage-extract` 再运行真实二进制）。
- 构建产物放 `~/packages/`（rsync `--delete` 不会清掉），`dist/` 同步回仓库。

## 四、验证

- 构建后先跑：Headless 5/5、e2e 6/6、selftest 9/9。
- 每种安装包跑 `verify-deb.sh`（安装→CLI→清理往返→GUI→卸载）与 `verify-others.sh`（解包+CLI）。
- GUI 真实渲染：WSLg 下 `xwd` 抓窗口转 PNG 人工核验。

## 五、已知的坑（务必阅读）

1. **不要在 /mnt/d（9p/DrvFs）上构建或运行 dotnet**：缓存导致读到旧文件/伪错误。先 rsync 到
   `/home/cleanmaster/build/linux` 再构建。
2. **不要用 PowerShell `Get-Content/Set-Content` 改写 UTF-8 源码**：会把中文注释读坏导致编译崩
   （已两度踩坑）。所有源码编辑用 Write/Edit 工具。
3. **PowerShell 会破坏内联 bash 脚本**（引号/管道/`$()`），复杂命令一律写 .sh 文件再 `wsl bash`。
4. **`dotnet sln add` 会在 sln 中生成垃圾 solution-folder 条目**；解决方案文件由手工维护
   （CleanMaster.Linux.sln，4 个真实项目），修改项目后不要用 `dotnet sln add`，直接编辑 sln。
5. **新增 csproj 后必须确认它进了解决方案**，否则 `dotnet build` 不会构建它（App 项目曾因此
   长期用旧 DLL，测试全挂但构建"成功"）。
6. **appimagetool 下载易截断**（官方 8,811,712 字节；截断文件自解压报 "Failed to open squashfs
   image"）。用断点续传脚本（build-appimage.sh 内置）或先 `curl -C -` 补全。
7. **GitHub release 下载在 WSL 内不稳定**（http=200 但中断）；失败时可从 Windows 宿主 curl 下载，
   或用 `api.github.com` 核对官方 size。
8. **WSLg 合成输入**：xdotool 的合成点击/按键不会路由到 WSLg 窗口（XTEST 不经过 Weston 输入管线），
   交互验证用 Avalonia.Headless 测试代替；窗口内容抓取用 `xwd`。
9. **rsync --delete 会删构建树内未入库的生成物**（图标、stage 等）：需入库的资产先同步回
   Windows 源（如 `installer/assets/icon`），纯构建产物放 `~/packages/`。
10. **dpkg-deb 校验命令的 `| head` 会触发 SIGPIPE 噪音**（"tar subprocess Broken pipe"），属正常。

## 六、发布流程

1. 全部测试通过 → 打包四种安装包。
2. 同步 `dist/` 到仓库，提交推送。
3. GitHub 创建 Release `v1.0.0-linux`，上传四个安装包 + 校验和。
4. 更新 `docs/验收记录.md` 的产物与校验和。
